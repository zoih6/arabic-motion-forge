# سلسلة الإنتاج ومعايير الخروج

| المرحلة | المدخل | الناتج الواجب | بوابة الخروج |
|---|---|---|---|
| intake | طلب المستخدم والحالة | brief + project.json | النواقص المؤثرة والخصوصية محسومة |
| research | السؤال والرسالة | sources + claim ledger | مصادر مناسبة، لا حقائق مخترعة |
| direction | المعنى والمراجع | style + originality + copy lock | هوية جديدة وموافقة صحيحة النطاق |
| shot design | القصة والتعليق | shotlist + layer-plan | لكل عنصر وظيفة وقنوات وتوقيت |
| technical proof | أصعب آلية | اختبار قابل للإعادة | native/equivalent/conditional معلنة |
| prototype | الأصول والنص | animatic/frames | سلامة العربية والحواف والقراءة |
| motion review | الزمن الكامل | مراجعة وسط الحركة | لا مجموعة تتحرك كملصق واحد بلا سبب |
| render | مصدر مقفل | أجزاء + frame manifest | عدد وفترات إطارات صحيحة وحفظ مؤكد |
| audio/merge | الأجزاء والمزيج | MP4 نهائي | صوت مستمر، PTS سليم، decode ناجح |
| delivery | النسخة المفحوصة | روابط وبصمات وحالة | الملف موجود ومتاح، لا وعود غير منفذة |

هذه ليست حالات توجب سؤال المستخدم عند كل انتقال. طلب التنفيذ الصريح يسمح بالاستمرار داخل النطاق؛ الحالات توقف عند نقص حقيقي أو قيد موافقة أو خطر نشر. في الإصلاح، أعد البوابة المتأثرة وما بعدها فقط.

قبل الرندر: افحص `project.json` و`layer-plan.json` وcopy hash. بعد الرندر: لا تعتمد على صور التصميم؛ افحص encoded frames والتوقيت والصوت الفعلي. سجّل حدود المراجعة، خصوصًا إن لم تتوفر أداة استماع.
